---
'@svelte-vitals/action': minor
---

Update the bundled analyzer to `svelte-vitals` 0.55.2 / `@svelte-vitals/core` 0.55.2. The action's inputs and outputs are unchanged, and the step still fails on `failOn` severity rather than on any score. What changes is what the scan reports:

- **Source analysis follows much more of the app, so findings move in both directions.** It now reads `src/app.html`'s `<head>`, components reached through barrels, namespace imports, locals (`<svelte:component this={X}>`, `$derived(cond ? A : B)`) and dynamic `import()`, `<svelte:head>` tags nested in `{#if}`/`{#each}`/`{#await}`/`{#key}`, components placed inside `<svelte:head>`, `#lib/*` package.json `imports`, workspace packages, `kit.alias` values that climb above the project root or are written as `path.resolve(…)`, and the `svead` meta package. Most routes lose false "Missing" findings, including critical `seo/title-presence`. But newly visible markup can surface new findings: a shell `<title>` in `app.html` is now reported by `seo/duplicate-title` and `seo/title-length` on every route, a `noindex` there by `seo/indexability`, and a followed component's `<h1>` can produce a `seo/single-h1` "Multiple `<h1>`" finding. The import-following rules, critical `security/handler-state-write` among them, also see modules they could not reach before, so **a step on the default `failOn: critical` that passes today can fail after this update.**
- **Results now depend on whether the workflow installs dependencies before this step.** Components from Svelte packages in `node_modules` are followed when the checkout is installed, and an `<h1>` inside one can produce a `seo/single-h1` finding located in `node_modules`. Without an install step the scan behaves as before.
- **Routes that never render, and code that never runs on the server, are no longer checked as if they did.** A page whose `load` redirects or throws `error()` on every path (including through `if`/`else`, `try`/`catch` and same-file helpers) is skipped by the route-level checks. `ssr = false` in the root layout or in a nested layout now applies to its subtree, so `correctness/server-browser-global`, `correctness/instance-browser-global`, `security/shared-state-import`, `security/handler-state-write` and `security/server-module-state` stop flagging the universal files and components that never render on the server.
- **Exclusive branches count as alternatives, which moves some finding locations.** Headings in the arms of one `{#if}`/`{#await}` block, a `<svelte:boundary>`'s `failed`/`pending` snippets, content a component renders in exclusive arms, and a component `{#if}` decided by a literal prop no longer add up, so `seo/single-h1` "Multiple `<h1>`" and `seo/heading-level-skip` false positives drop. When a folded `<h1>` was where a remaining "Multiple `<h1>`" finding pointed, the finding now points at the next one, so a suppression recorded for the old location no longer matches. `a11y/top-level-landmark` now reports a landmark under a non-landmark `<header>`/`<footer>` against the landmark around it ("nested inside main" instead of "nested inside banner"); recorded suppressions still match by location, so check those entries.
- **Two new `a11y` findings from the updated HTML spec dataset.** `a11y/disallowed-aria-props` (warning) reports `aria-label`, `aria-labelledby` and `aria-braillelabel` on `role="tooltip"`, and `a11y/permitted-contents` reports an HTML element placed directly inside `<math>` as `info`.
- **`performance/namespace-import` is recalibrated.** It reports `import * as X` only when `X` is used as a whole (indexed by a variable, passed on, spread or enumerated). Static member access such as `X.foo()` or `<X.Component />` tree-shakes like named imports and is no longer reported.
- **Fewer false positives across the correctness and performance rules.** `correctness/each-key` and `correctness/each-index-key` skip constant lists, whether same-file or imported, and length-only placeholders. `correctness/prop-mutation` accepts the legacy `export let` update idioms. The browser-global rules accept `typeof x === 'function'` and SvelteKit 3's `$app/env` as guards. `performance/responsive-image` skips SVG images and `<picture>` fallbacks. `performance/sequential-awaits` and `performance/load-waterfall` track data dependencies through conditionals, loops and pushed lists. One guard is gone: `browser || …` is no longer treated as a browser guard, because its right-hand side runs on the server, so such reads are now reported.
- **Some findings change wording but keep their key.** `seo/og-title`, `seo/og-description`, `seo/og-image` and `seo/og-url` written as `<meta name="og:…">` now say to use `property=` instead of "Missing", and existing suppressions still apply to them. `seo/twitter-card` accepts `<meta property="twitter:card">`. `a11y/id-duplication` recommends `$props.id()` when the duplicate comes from one component rendered more than once.
- New opt-in config switch `seo: { indexable: false }` for projects that never appear in search results. It turns off `seo/canonical-url`, `seo/og-title`, `seo/og-description`, `seo/og-image`, `seo/og-url`, `seo/twitter-card`, `seo/json-ld`, `seo/sitemap-xml`, `seo/sitemap-in-robots`, `seo/title-length`, `seo/description-length`, `seo/indexability`, `seo/description-presence`, `seo/duplicate-title`, `seo/duplicate-description`, `seo/hreflang` and `seo/ssr-disabled`, and an explicit `rules` entry still wins. It has no effect until it is set.

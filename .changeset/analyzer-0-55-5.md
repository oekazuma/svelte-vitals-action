'@svelte-vitals/action': minor
---

Update the bundled analyzer to `svelte-vitals` 0.55.5 / `@svelte-vitals/core` 0.55.5. The action's inputs and outputs are unchanged, and the step still fails on `failOn` severity rather than on any score. Most of what changes removes false positives, but some existing rules now report more, so findings move in both directions:

- **`security/handler-state-write` (critical) changes what it reads as server-only, so a step on the default `failOn: critical` can start or stop failing.** Any `server` directory outside `src/routes` and `static`, and any file named `*.server.*`, now counts like `src/lib/server`, and a handler's `.set()`/`.update()` on an export from one is reported only when that export is positively an in-memory store. An export initialized with `writable(…)` from `svelte/store` is such a store, so a write to one in `src/lib/server` is now reported, and a write through a namespace import (`stores.user.set(…)`) is matched against the member it writes to. It no longer reports database-client calls such as `prisma.post.update({ … })` or `db.update(table).set({ … })`, client objects (`new KvService()`, `drizzle(url)`, `createClient(…)`), all-function facades in `$lib/server`, or writes only the browser reaches (`if (browser)`, `browser && …`, after `if (!browser) return;`). When a write moves out of this rule into a `.svelte.ts` module with module-scope `$state`, it can show up as a `security/shared-state-import` warning instead, which a recorded `handler-state-write` suppression does not cover.
- **More routes are read as never rendering, and route-level checks such as `seo/title-presence` skip them:** a page or layout whose `load` redirects or errors on every call (including through an imported factory, a `return redirect(…)` guard, an `if (building)` branch, or a feature flag exported as the literal `false`), a component script that throws on every render, a path `handle` in `src/hooks.server.ts` answers before `resolve`, and an app with `kit.router.type: 'hash'`. `export const ssr = dev` and `csr = dev` are read as `false`, so the SSR-only rules exempt those routes, while `seo/ssr-disabled` now reports `ssr = dev`.
- **`seo/heading-level-skip` reads headings in document order across layouts, snippets and components**, and counts `role="heading"` elements and bits-ui `Dialog.Title`/`AlertDialog.Title` by their level. A page heading that skips from a component's heading (a `PageHeader` `<h1>`, then the page's `<h3>`) is now reported, and many skips that were only an artifact of reading order disappear.
- **`{#if}` arms are decided in many more cases**, per route (`page.route.id`, `page.url.pathname`, Sets and arrays of route ids) and per component use (combined prop tests, `$derived` props, `{:else if}` chains, `.length` tests, message functions). `seo/single-h1`, `seo/heading-level-skip`, `a11y/id-duplication`, `a11y/duplicate-landmark` and `a11y/top-level-landmark` no longer count arms a route cannot render, which mostly drops findings but can leave a route with no `<h1>`.
- **`seo/canonical-url` and `seo/description-presence` drop from `warning` to `info`** on a route whose server `load` sends a request without a session away first (`if (!locals.user) redirect(…)`, `error(401)`). A `rules` severity for either still applies.
- **Head tags in an `{#if}` that opens only after mount** (`let ready = $state(false)`, set in `onMount`/`$effect`) no longer count on server-rendered routes, so such a route can now report a missing `<title>`, description, canonical, Open Graph or JSON-LD. Conversely, `document.title` set on never-server-rendered routes now counts for `seo/title-presence`, and a `handle` that fills an `app.html` `<head>` comment through `transformPageChunk` is read as supplying the meta tags.
- **Config passed to `sveltekit()` in the Vite config is now read** for `alias`, `files.lib` and `router.type`, so modules behind an alias declared there are followed and rules can report in files they did not reach before.
- **Fewer false positives elsewhere**, including `correctness/each-key`/`each-index-key` (constant lists through aliases, casts and imports), `correctness/prop-mutation`, `correctness/unmutated-state`, `correctness/effect-as-derived`, `correctness/base-path-navigation`, the browser-global rules, `performance/sequential-awaits`/`load-waterfall`, `performance/responsive-image` (QR codes), `performance/render-blocking-script`, `performance/preconnect`, `seo/json-ld`, `seo/json-ld-validity`, `seo/sitemap-xml` and `a11y/disallowed-aria-props` (svelte-dnd-action zones).
- **Components that failed to parse or were skipped are now analyzed:** a `.svelte` file with a byte order mark is read at the right offsets, and one declaring a local under the name of one of its `$state`s no longer fails to parse, so their findings appear. Very large source files no longer slow analysis down quadratically, which had pushed some scans past the job time limit.
- **Some messages change wording but keep their key.** `correctness/base-path-navigation` gives the SvelteKit 3 `resolve('blog/…')` spelling next to the SvelteKit 2 one, and the browser-global fix hints name `$app/env` next to `$app/environment`.
